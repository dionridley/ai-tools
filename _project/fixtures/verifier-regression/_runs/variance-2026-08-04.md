## Protocol

- **0 void runs, 0 discards**, against the widened check (`_answers`, `_runs`,
  `verifier-regression-baseline`, `verifier-variance-study`, `014-optimize-plan-verifier`).
- **Three runs read the fixtures `README.md`** — r17, r04, r06, all Arm B. Ruled **not void**: the
  README is not an answer key and the fixture directory names already announce the defect class.
  Only r17 visibly changed behaviour (its recommendations pivot to "do not fix the artifacts"), and
  that framing was excluded from its extra-findings count. **The asymmetry — three Arm B runs, zero
  Arm A — is recorded, not explained. n=3 cannot distinguish a definition effect from chance.**
- Several runs disclosed noticing `_answers/` and declining to open it. Disclosure of a refusal is
  not contamination.
- One run noticed `plan-verifier.md` was staged as modified — the study's own apparatus — and
  correctly flagged it as unrelated to its phase rather than reporting it as a defect.

## Two factual errors, one per arm

- **r13 (Arm B, F1)** asserted `plan-base.md:209` is byte-identical to `create-mode.md:192`. It is
  not — they differ by the word `all`. **The report contradicts itself:** its own md5 table lists
  the two lines under different hashes. Scoring reproduced all five hashes; the table is right and
  the prose is wrong.
- **r24 (Arm A, F2)** claimed `audit-guide.md:6-10` gives the abstract form
  `[NEEDS REVIEW YYYY-MM-DD: reason]`. The guide contains **zero** occurrences of `YYYY-MM-DD`.
  That form lives only at `plan.md:17` — and it is exactly the fact that would have carried r24 to
  D3, the defect it missed.

## Key correction produced by this study

`_answers/f3.md` gained a **Known additional finding** section. `rendered.md` contradicts itself —
`:10` triggers on suspicion, `:14` requires confidence — and **5 of 6 F3 runs found it**, one
mis-citing `:10` as `:11`. The key had omitted it. Not promoted to a planted defect: detection stays
`/2` so scores remain comparable with the 2026-08-02 baseline.

This is the second time a run has corrected this harness's own key; `_answers/f4.md` carries the
first.
