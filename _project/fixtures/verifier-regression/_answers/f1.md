# Answer key — F1: self-review drift

See `../README.md`.

**Fixture type:** REAL. Snapshotted from `main` on 2026-08-02, before plan 014 Phase 2 fixed it.

**Target:** `f1-self-review-drift/plan.md`, Phase 1.

## Planted defects

All four are checkable without running the verifier, by extracting the lines and comparing bytes.

### D1 — `plan-base.md:209` carries `no`-shape wording inside the `yes`-shape gate

The gate block at `sites/plan-base.md:203–209` is the `yes` shape: it contains the
independent-verification task and the Apply task. Its final line reads

> Re-read Tasks above. **Flip `[x]` only for tasks whose Verification passed.** …

which is the `no`-shape instruction. It keys the flip to the plan's **Verification command
block**, while `:208` immediately above keys it to **the verification's verdict**. A task whose
command passed but whose verifier verdict was FAIL is flippable under the gate's last line.

Falsifies: Task 3, Acceptance Criterion 2, Acceptance Criterion 3.

### D2 — the two `yes`-shape reference sites are not identical

- `sites/create-mode.md:181` ends *"…follow-up **in future phases or the Retro**."*
- `sites/questions-mode.md:186` ends *"…follow-up."*

The routing destination is dropped at the second site.

Falsifies: Task 1, Verification item 1, Acceptance Criterion 1.

### D3 — the two `no`-shape sites are not identical

- `sites/create-mode.md:192` — *"…stays `[ ]` with a short note **explaining why**."*
- `sites/questions-mode.md:199` — *"…stays `[ ]` with a short note."*

Falsifies: Task 2, Verification item 2, Acceptance Criterion 1.

### D4 — `plan-base.md`'s gate carries no UNVERIFIED routing at all

Because `:209` is the `no`-shape text, the instruction to note UNVERIFIEDs for follow-up is
absent from the base template entirely. UNVERIFIEDs die at the phase boundary in every plan
generated from it.

Falsifies: Task 4, Acceptance Criterion 4.

## Scoring

Detection = defects reported / 4.

A verifier that reports "the three `yes`-shape sites are not byte-identical" without separating
the `plan-base` case (D1) from the `create-mode`/`questions-mode` case (D2) scores **1 of 2** for
those two — they are different defects with different fixes, and conflating them would send a
reader to the wrong file.

D1 is the one that matters most: it is the defect that actually shipped in 3.3.0, and the one a
real verifier found unprompted on 2026-08-02 while verifying an unrelated phase.

## Note on a third variant

`plan-base.md:209` also differs from `create-mode.md:192` — it says *"Re-read Tasks above"* where
the `no`-shape sites say *"Re-read **all** Tasks above."* So there are five instances and five
distinct texts. This is **not** scored separately; it is subsumed by D1, since fixing D1 replaces
the line wholesale. Credit it as a bonus observation if a verifier reports it.
